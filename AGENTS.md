# Codex Notes for LettuceAI Website

This file is a repo map for future agent updates. Read it before rescanning the
whole project.

## Project Shape

- This is a Vite 7 + React 19 + TypeScript website.
- Styling is Tailwind CSS v4 through `@tailwindcss/vite`, with shadcn/Radix-style
  primitives in `src/components/ui`.
- Path alias: `@/*` maps to `src/*`.
- Main entry:
  - `src/main.tsx` hydrates prerendered HTML in production and uses `createRoot`
    in dev.
  - `src/App.tsx` owns routing, Helmet provider, snow context, and the split
    between docs and non-docs layouts.
- Build command: `npm run build`.
- Dev command: `npm run dev`.
- Lint command: `npm run lint`.
- There is both `package-lock.json` and `bun.lock`, but `package.json` scripts
  are npm-oriented and previous verification used `npm run build`.

## Do Not Edit These by Hand

- `dist/` is generated by `npm run build`.
- `.prerender/` is temporary generated output and is removed by
  `scripts/prerender.mjs`.
- `node_modules/` is installed dependencies.
- `public/docs/graphs/*.svg` are generated graph assets from Mermaid sources in
  `docs/diagrams/*.mmd`; update the Mermaid source first when changing diagrams.

## Routing

All routes are in `src/App.tsx`.

There are two route trees:

- Docs routes: `location.pathname.startsWith("/docs")` renders `DocsLayout`
  directly, without the landing navbar/footer.
- Non-doc routes: render inside `Layout`, which adds the landing `Navbar` and
  `Footer`, then `AnimatedRoutes`.

Current public non-doc routes include:

- `/`
- `/download`
- `/providers`
- `/faq`
- `/privacy`
- `/terms`
- `/license`
- `/changelog`
- `/convert`
- `/discord` redirects to `links.discord`
- `/blog`
- `/blog/:slug`
- `/blog/end-of-lettuceai` external redirect
- `*` renders `NotFoundPage`

Docs routes are nested under `/docs` in `App.tsx`; each doc page also needs a
matching export from `src/pages/docs/index.ts`.

When adding a new route, consider all of these:

- Add the route in `src/App.tsx`.
- Add route exports in `src/pages/index.ts` or `src/pages/docs/index.ts`.
- Add SEO via `src/components/common/SEO.tsx`.
- Add it to `src/prerender/entry-server.tsx` if it should be statically
  prerendered and have a `.md` companion.
- Add it to `public/sitemap.xml` if it is indexable.
- For Vercel-level redirects, add an entry to `vercel.json` before the SPA
  rewrite.

## Deployment, Prerendering, and AI Markdown

`npm run build` runs:

1. `tsc -b`
2. `vite build`
3. `vite build --ssr src/prerender/entry-server.tsx --outDir .prerender`
4. `node scripts/prerender.mjs`

`src/prerender/entry-server.tsx` exports `prerenderRoutes`. Add routes there
when the final static site should ship prerendered HTML and a generated Markdown
copy.

`scripts/prerender.mjs`:

- Loads `dist/index.html` and the SSR bundle.
- Renders every route.
- Hoists React 19/Helmet metadata into `<head>`.
- Writes HTML into `dist/<route>/index.html`.
- Writes LLM-friendly Markdown companions as `dist/<route>.md` and
  `dist/index.md`.
- Uses Turndown with GFM and strips layout/noise tags from Markdown.

`vercel.json`:

- Has a `/discord` 302 redirect to the Discord invite.
- Redirects recognized AI user agents from HTML routes to `.md` route
  companions.
- Rewrites all non-API paths to `/` for SPA fallback.
- Sets text/markdown headers for `*.md`, and cache/content headers for
  `robots.txt`, `sitemap.xml`, `llms.txt`, and `ai.txt`.

`public/llms.txt`, `public/ai.txt`, `public/robots.txt`, and
`public/sitemap.xml` are hand-maintained public SEO/AI-crawler surfaces. Keep
them synchronized with major product, route, and policy changes.

## Layouts and Navigation

Landing/public pages:

- `src/components/layout/Layout.tsx` wraps children in
  `src/components/landing/Navbar.tsx` and `Footer.tsx`.
- `Navbar.tsx` has its own `NAV_LINKS` array. Update it when top-level nav
  changes.
- `Footer.tsx` has local `footerLinks`. Update it separately.
- Shared URLs live in `src/config/links.ts`.
- Shared image URLs live in `src/config/images.ts`.

Docs pages:

- `src/pages/docs/DocsLayout.tsx` composes `DocsNavbar`, `DocsSidebar`,
  `DocsPagination`, and `TableOfContents`.
- `src/config/docs-nav.ts` is the source of docs sidebar sections, icons,
  keywords, and `allDocsItems`.
- `DocsPagination` uses `allDocsItems`, so docs order is controlled by
  `docs-nav.ts`.
- `DocsNavbar` contains source-based search and links to GitHub/Discord.
- `TableOfContents` reads rendered `h1`, `h2`, `h3` elements that have IDs.
  Use `DocHeading` for docs section headings so anchors and TOC work.

## Adding or Updating Docs Pages

Docs are hand-authored TSX files in `src/pages/docs`, not Markdown.

For a new doc page:

1. Create `src/pages/docs/MyDoc.tsx`.
2. Export it from `src/pages/docs/index.ts`.
3. Import and route it under the `/docs` route tree in `src/App.tsx`.
4. Add it to `src/config/docs-nav.ts` with useful keywords.
5. Add an entry to `sourceByHref` in `src/lib/docs-search.ts`; search indexes raw
   TSX source, not rendered DOM.
6. Add the route to `src/prerender/entry-server.tsx`.
7. Add the URL to `public/sitemap.xml` if it is public/indexable.

Docs authoring conventions:

- Use `<SEO>` with `buildBreadcrumbSchema`.
- Wrap body in `motion.article` with `className="prose prose-invert max-w-none"`.
- Use `DocHeading` for anchorable headings.
- Use `Callout`, `DocSplit`, `DocImage`, and `CodeBlock` where they match
  existing pages.
- Use `images` from `src/config/images.ts` for externally hosted screenshots and
  generated diagrams.

## Blog

Blog posts are Markdown files in `src/content/blog`.

- Loader: `src/lib/blog.ts`.
- It uses `import.meta.glob("../content/blog/*.md", { eager: true, query:
  "?raw" })`.
- Slug comes from frontmatter `slug` or from the filename after stripping the
  leading `YYYY-MM-DD-`.
- Posts are sorted descending by `date`.
- `BlogPage` picks the first `featured: true` post, otherwise the newest post.
- `BlogPostPage` renders HTML with `dangerouslySetInnerHTML`.
- Mermaid fenced code blocks are converted to `<div class="mermaid">` and then
  rendered client-side in `BlogPostPage`.

Blog frontmatter keys used by code:

- `slug`
- `title`
- `date`
- `excerpt`
- `author`
- `avatarUrl`
- `categories` or `category` as comma-separated text
- `cover`
- `featured`

When adding a blog post:

- Add the Markdown file under `src/content/blog`.
- Confirm `getAllSlugs()` includes it via the build; prerender routes include
  all blog slugs automatically.
- Update `public/sitemap.xml` manually if the post should be in the sitemap.

## Changelog

Changelog entries are Markdown files in `src/content/changelog`.

- Loader/parser: `src/lib/changelog.ts`.
- Slug comes from frontmatter `slug` or filename after stripping the leading
  `YYYY-MM-DD-`.
- Entries sort by date descending, then slug descending.
- Frontmatter keys used by code:
  - `version`
  - `platforms` comma-separated
  - `date`
  - `title`
  - `tagline`
  - `githubUrl`
- Body parsing:
  - Intro content before the first `##` becomes `intro`.
  - `## Heading` creates sections.
  - `-` or `*` lines become bullet items.
  - `>` lines become quote items.
  - Inline markdown support is deliberately limited to backticks, bold, and
    italic in `renderItem`.
- `ChangelogPage` maps section title keywords to icons locally in its `ICONS`
  table.

## Download Page and Releases

`src/pages/DownloadPage.tsx` uses `src/hooks/useLatestRelease.ts`.

Release API:

- Fetches `https://api.github.com/repos/LettuceAI/app/releases?per_page=40`.
- Supports `family`: `android` or `desktop`.
- Supports `channel`: `release` or `dev`.
- Can target an exact release with `release` query param.

Tag expectations:

- Stable tags look like `android-release-x.y.z` or `desktop-release-x.y.z`.
- Dev tags look like `<family>-dev-<number>-<number>-<hash>`.

Asset filename expectations:

- Android: any `.apk`.
- Windows: `windows-cpu.zip`, `windows-cuda.zip`, `windows-vulkan.zip`.
- Linux: `linux-cpu.zip`, `linux-cuda.zip`, `linux-vulkan.zip`.
- macOS legacy: `macos-cpu.dmg`, `macos-metal.dmg`.
- macOS split: `macos-x64-cpu.dmg`, `macos-x64-metal.dmg`,
  `macos-arm64-cpu.dmg`, `macos-arm64-metal.dmg`.

The page reads query params such as `platform`, `channel`, `release`,
`version`, `fallback`, and `source=in-app-update`.

## Converter

`src/pages/ConvertPage.tsx` is a browser-only character card converter.

Relevant libs:

- `src/lib/png-parser.ts`: extracts base64 JSON from PNG `tEXt`/`iTXt`
  `chara` chunks.
- `src/lib/chara-to-uec.ts`: converts Chara v1/v2/v3-ish records to UEC v2.
- `src/lib/uec-to-chara.ts`: converts UEC character records to Chara v2/v3.
- `src/lib/png-writer.ts`: embeds Chara JSON into a PNG `tEXt` `chara` chunk.
- Uses `unified-entity-card` for UEC creation/stringification.

The converter accepts PNG character cards, `.uec`, and JSON UEC files. It only
supports UEC kind `character`.

## SEO and Schema

- Shared SEO component: `src/components/common/SEO.tsx`.
- Defaults are for `https://lettuceai.app`.
- `SEO` sets title, description, canonical URL, Open Graph, Twitter, optional
  `noIndex`, and optional JSON-LD.
- Shared schemas live in `src/config/schemas.ts`:
  - `organizationSchema`
  - `softwareSchema`
  - `websiteSchema`
  - `buildFaqSchema`
  - `buildBreadcrumbSchema`
  - `providerListSchema`
  - `converterSchema`

If a page is meaningful for search, give it a specific title/description and
schema where applicable.

## Styling Notes

- Global CSS is in `src/index.css`.
- Fonts:
  - Sans: `Noto Sans Variable`
  - Display: `Fraunces Variable`
- Main theme is dark by default via `<html class="dark">` and the app wrapper
  `className="dark grain min-h-screen bg-background text-foreground"`.
- Primary brand color is a lettuce green OKLCH token.
- There is a fixed noise overlay using `.grain::before`.
- Scrollbars are hidden globally.
- `.prose` styles are custom and affect docs and blog body content.
- `.blog-content` adds blog-specific table, blockquote, heading, and Mermaid
  styling.

Design tendency in this repo:

- Dark, restrained, high-contrast marketing site.
- Landing sections are custom components in `src/components/landing`, not a
  generic CMS system.
- Many sections use Framer Motion.
- Prefer existing UI primitives and local visual language before introducing new
  component styles.

## Shared Config and Content

- `src/config/links.ts`: canonical external URLs (`discord`, `github`,
  `githubRepo`).
- `src/config/images.ts`: canonical hosted image URLs for logo, screenshots,
  providers, docs screenshots, and diagram images.
- `src/config/faq.ts`: FAQ content used by FAQ/home sections.
- `src/config/docs-nav.ts`: docs nav and search keyword metadata.
- `src/config/schemas.ts`: structured data helpers.

When a global link, image, FAQ answer, or schema fact changes, update the config
file first and then references only if the page uses hard-coded duplicate text.

## Snow / Holiday Behavior

- `src/contexts/SnowContext.tsx` controls snow enablement and holiday-season
  detection.
- `AppContent` renders `react-snowfall` only when hydrated, during holiday
  season, enabled, and not on docs pages.
- `Navbar` exposes the snow toggle only during holiday season.

## Marketing Folder

`marketing/` contains written launch, Discord, Reddit, and blog-support material.
It is not part of the Vite app runtime, but it is useful source context when
writing announcements or release copy.

## Validation Habits

For code changes, prefer:

- `npm run build` for full verification because it runs TypeScript, client
  build, SSR build, and prerender.
- `npm run lint` for lint-only checks.

Expected build warnings that may appear without indicating failure:

- Large chunk warnings, mostly from Mermaid/Remotion/client bundle size.
- Remotion license notice from build/prerender output.

## Common Update Checklists

Add a public page:

- Page component under `src/pages`.
- Export from `src/pages/index.ts`.
- Route in `src/App.tsx`.
- SEO/schema.
- Nav/footer links if user-facing.
- `src/prerender/entry-server.tsx`.
- `public/sitemap.xml`.

Add a docs page:

- Page component under `src/pages/docs`.
- Export from `src/pages/docs/index.ts`.
- Route in `src/App.tsx`.
- Entry in `src/config/docs-nav.ts`.
- Entry in `src/lib/docs-search.ts`.
- Entry in `src/prerender/entry-server.tsx`.
- Entry in `public/sitemap.xml`.

Add a blog post:

- Markdown in `src/content/blog`.
- Include frontmatter.
- Confirm cover image URL if provided.
- Build to ensure slug is prerendered.
- Update sitemap manually when needed.

Add a changelog entry:

- Markdown in `src/content/changelog`.
- Include frontmatter.
- Use `##` section headings and bullet/quote lines only.
- Build and inspect page if formatting is non-trivial.

Add an external redirect:

- Add Vercel redirect in `vercel.json` before the SPA rewrite.
- Optionally add client fallback route with `ExternalRedirect` in `src/App.tsx`
  if local/dev behavior matters.
- Prefer `links.ts` for shared destinations.

## Known Footguns

- Docs search will silently miss a new page unless `sourceByHref` in
  `src/lib/docs-search.ts` is updated.
- New docs routes will not get generated `.md` companions unless
  `src/prerender/entry-server.tsx` is updated.
- `public/sitemap.xml` is hand-maintained and can become stale.
- The README project tree is older than the current repo and misses blog,
  changelog, prerendering, converter, and marketing details.
- `index.html` contains baseline SEO/schema. Per-route Helmet output replaces
  many defaults during prerender, but global baseline changes may need both
  `index.html` and `SEO.tsx`/schemas updated.
- `DocsNavbar` has a hand-drawn Discord SVG while landing nav/footer use
  `react-icons/fa`.
- `docs-nav.ts` has repeated `lorebook` keywords; harmless but noisy.
- Some comments and display text use punctuation/non-ASCII. Keep existing style,
  but default new code/docs to ASCII unless there is a reason.
