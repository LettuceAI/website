## Highlights

- **Companion template precedence fixed** — companion mode resolves the character's companion prompt template before the session template, so an active session template no longer overwrites the companion prompt
- **Relationship state with meaning** — every axis is now sent as a band, a short behavioral gloss, and the raw score on its scale, instead of a bare label
- **Smart Creator on strict local templates** — models like Gemma that only accept one system message no longer fail during character generation
- **Group chat memory mode sticks** — picking dynamic memory during group creation no longer falls back to manual
- **Forced reasoning for Gemma4** — a per-model toggle makes Gemma4-series models on llama.cpp think before they answer, with the thought routed to the reasoning view
- **OpenRouter Image API** — image generation goes through OpenRouter's dedicated Image API, fixing OpenAI image models that finished without an image, with clearer provider errors and automatic downsizing of oversized reference images

---

## Companions

- **Companion prompt template wins over the session template**: previously an active session template took precedence in companion mode and overwrote the companion prompt; the prompt debugger now reports the same source order
- The **relationship-state line** shows each axis as `label - gloss (value on a scale from ...)`, giving the model the word, what it means, and the exact score
- **Trust, closeness, and affection** moved to a seven-step scale, adding bands such as open, avoidant, and indifferent, with trust and closeness keeping a deliberately positive-skewed neutral zone
- **Tension** has named bands from calm to at breaking point instead of being emitted as a bare percentage

## Smart Creator

- On **llama.cpp**, the creation helper's system entries are merged into one leading system message, so chat templates that require a single system message (such as Gemma) no longer fail with "System message must be at the beginning"
- **Remote providers** keep the system entries separate, preserving the authored block structure

## Group Chats

- **Memory mode chosen at creation is kept**: the group is created with the selected mode instead of defaulting to manual, so dynamic memory no longer has to be re-enabled from group settings afterwards

## Reasoning

- **Force Reasoning in Gemma4-series models** is a new toggle in the Reasoning section of the model settings, shown only for the local llama.cpp engine
- When enabled, the system prompt starts with the `<|think|>` opener and the reply is prefilled with an open thought channel, so the model begins its turn inside a thinking block without editing the system prompt by hand
- The **thinking parser starts inside the reasoning block**, so the forced thought lands in the reasoning field for both streamed and final messages instead of leaking into the visible reply
- The final prompt, including the prefill, is visible in the llama.cpp debug payload

## Image Generation

- **OpenRouter uses the Image API** (`/api/v1/images`) instead of chat completions, so the generated image comes back directly; models not served there fall back to the chat endpoint automatically
- **OpenAI image models on OpenRouter** such as gpt-5.4-image-2 no longer finish with an empty reply and no image
- **Provider errors delivered inside a successful response**, such as an upstream 504, are shown with their code and message instead of failing with "missing field `choices`"; transient server errors are retried once
- **Oversized reference images are downsized** to 2048 px on the longest edge and re-encoded when larger than 4 MB, with the inpainting mask resized to match, so upscaled sources no longer trigger HTTP 413
- A request that is still too large explains that the reference image should be smaller instead of showing a bare 413
- Base64 image payloads are truncated in the image generation log

## Local Models

- **Adaptive-p sampler controls reach llama.cpp**: the target and decay values were dropped from every request, so the sampler ran without them
- The **debug view no longer shows an OpenAI URL** for local llama.cpp requests; unregistered providers default to a localhost base URL
