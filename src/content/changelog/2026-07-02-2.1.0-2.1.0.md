## Highlights

- **Multi-GPU local models** — llama.cpp now distributes a model's layers across every selected GPU, with automatic or manual layer splits, KV cache placement modes, a main-GPU pin, and per-GPU VRAM reservation so nothing overflows
- **Performance metrics** — a new local-LLM performance page graphs tokens per second, prompt and generation timing per run and across runs, with a per-message action to see exactly how any reply was produced
- **MTP stats per message** — speculative-decoding acceptance and draft stats are now persisted and shown on each message
- **OpenRouter provider pinning** — pick a specific provider endpoint per model, with live pricing, cache rates, uptime, and provider logos, and route every request exclusively through it
- **Sprout hardware probe** — remote Ollama runnability is now judged against the real hardware behind the endpoint instead of a guess
- **SillyTavern-compatible export** — chat export and import now speak the official SillyTavern jsonl format, so histories move cleanly in and out
- **Shared memory cycle hub** — a single unified memory-cycle panel across both chat and group memory pages
- **Mobile model browser** — browse HuggingFace on your phone and pull GGUF models straight to a remote Ollama host, with files and recommended settings in a slide-in drawer

## Local Models (llama.cpp)

- **Multi-GPU layer distribution** across selected devices, with automatic or manual splits and a per-model single-GPU device override
- **KV cache placement modes** and per-GPU KV VRAM reservation when distributing layers, so the cache lands where it fits
- **Main-GPU pin** mapped to the correct device-list position, with the resident model unloaded before planning so budgets reflect the incoming model
- Multi-GPU distribution and KV modes explained inline with bottom-menu pickers, fully localized in the model editor
- **Per-message MTP speculative-decoding stats** persisted and displayed
- A notice when vision **disables MTP**, and a warning when a manual layer split exceeds a device's reported VRAM before loading
- Immediate aborts now **skip model load** entirely by checking the abort signal before the engine starts
- Bumped the llama-cpp-rs fork for an abort-crash fix and upstream sync

## Performance Metrics

- New **local LLM performance page** with per-generation and cross-run graphs
- Per-generation telemetry captured for every local reply, including in group chats
- Generations are **linked to their messages**, with a per-message action to open that reply's performance detail

## Providers

- **OpenRouter per-model provider pinning**: fetch endpoint metadata (pricing, cache rates, uptime, provider logos) in the model settings picker, persist the chosen endpoint, and route OpenRouter requests exclusively through it
- OpenRouter requests now send the **roleplay category** and current **app-attribution** headers
- **Sprout hardware probe** feeds remote Ollama runnability scoring, matched with translated provider and runnability strings

## Mobile

- The **HuggingFace model browser now works properly on phones** — on mobile it pairs with a remote Ollama provider, auto-selected when you have one and a required pick when you have several, with local-only downloads hidden
- **Files and recommended settings** open in a right-side drawer instead of the desktop side panel
- The **search bar expands** over the filter and destination controls while you type, and the sort bar collapses inactive options to icons so everything fits
- **Installed models** on mobile focuses on Ollama, with a reorganized toolbar, an inline provider selector, and model rows that keep the delete action beside the name
- The **download destination picker** was redesigned as a grouped list, and your destination choice now persists while you navigate
- The **real Ollama logo** is used across Ollama surfaces on both desktop and mobile

## Data & Backup

- Chat **export and import** rebuilt around the official **SillyTavern jsonl** format
- Backup and sync now **preserve current data** instead of overwriting it
- **Companion mode data** is preserved in unified export/config app settings

## Memory & Embeddings

- **Shared memory cycle hub** unifies the memory-cycle UI across chat and group memory pages, with strings translated into every locale
- **Explicit dynamic-memory model selection** is preserved instead of falling back to a default
- Shared-memory owner resolution now **honors companion character mode**
- Windows are **retried after a dynamic-memory failure** instead of being skipped
- Fixed a **re-embedding loop**, and de-duplicated lorebook scans and embedding-preference reads
- Embedding signatures are stamped from the **actual vector** to stop spurious vector migrations, and embedding migration markers survive the session schema round-trip
- The embedding tokenizer is resolved from the **version-specific file** instead of a hardcoded `tokenizer.json`

## Reliability & Fixes

### Local models (llama.cpp)
- Added a **smart multi-GPU offloader** that spreads large models across all your hardware, sizing each device's share automatically and keeping far more of the model on the GPU instead of falling back to the CPU
- **Per-GPU KV cache VRAM** is reserved when distributing layers, so the cache no longer overflows a device
- Immediate **aborts skip model load** by checking the abort signal before the engine starts

### Memory & embeddings
- Fixed a **re-embedding loop**, and de-duplicated lorebook scans and embedding-preference reads
- Embedding signatures are stamped from the **actual vector** to stop spurious vector migrations
- **Embedding migration markers survive** the session schema round-trip
- The embedding tokenizer is resolved from the **version-specific file** instead of a hardcoded `tokenizer.json`
- Upgrading from 2.0.0 **silently installs the v4 embedding tokenizer** once if the model was present without it, so token counting resolves after the update
- **Windows are retried after a dynamic-memory failure** instead of being skipped
- **Explicit dynamic-memory model selection** is preserved instead of falling back to a default
- Shared-memory owner resolution **honors companion character mode**

### Backup & data
- Backup and sync now **preserve current data** instead of overwriting it
- **Companion mode data** is preserved in unified export/config app settings

### Desktop, TTS & discovery
- macOS: keep **native decorations and an opaque window** so the traffic lights and rounded corners render correctly
- TTS: **ONNX Runtime is bundled on Windows** and Kokoro is routed through a shared runtime init (also bundled into Linux and Windows dev builds)
- Chat appearance: a per-conversation override no longer injects defaults that **clobber global settings**
- Discovery: card image URLs are rebuilt for the new **ct-cards storage host** with the required query params
