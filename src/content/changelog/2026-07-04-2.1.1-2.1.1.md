## Highlights

- **Device sync rebuilt** — conflict resolution now keeps the newest data instead of the oldest, a fresh install no longer overwrites the host's real settings with its own defaults, memory metadata survives the transfer intact, and large libraries sync in chunks with no more transfer size ceiling
- **Honest sync results** — a failed or interrupted sync now ends in a visible error instead of a fake "completed", and syncing onto a fresh install treats the host device as the source of truth
- **Multi-GPU that tells the truth** — a leftover single-GPU pin can no longer silently disable multi-GPU, and the model editor now shows the effective GPU setup a model will really use, including settings inherited from global defaults
- **Five new guided tours** — the local model editor, runtime defaults, the model browser's recommendation panel, group chats, and dynamic memory now walk you through themselves on first visit
- **ASR learning data everywhere** — your custom vocabulary, corrections, and dismissed suggestions now travel with both device sync and backups
- **Safe model file deletion** — deleting a GGUF or mmproj file warns you when a configured model still uses it, without blocking you

## Device Sync

- **Conflict resolution fixed**: the newest change wins across devices; previously the oldest version of every record was kept, which could discard the host's settings, prompt templates, and advanced settings
- Syncing onto a **fresh install** no longer competes with the host: the incoming data is authoritative until you finish onboarding
- **Memory metadata survives sync**: importance, categories, timestamps, and embedding versions arrive intact instead of being silently stripped to bare text
- **Chunked transfers** remove the previous hard size ceiling on large chat libraries, and each data domain is applied and finalized as it completes
- **Companion data, creation helper drafts, and ASR learning data** now sync alongside everything else
- The post-sync **embedding model prompt** now also triggers when the synced data itself contains memories, even if settings arrive misconfigured
- A sync that fails or loses connection mid-transfer now reports a **real error** instead of completing silently with partial data
- Sync state resets are **atomic**, and early connection failures are handled gracefully

## Local Models & Multi-GPU

- A per-model or global **single-GPU pin no longer silently disables multi-GPU**: enabling multi-GPU at the same or broader level now takes precedence, and a deliberate per-model pin still wins where intended
- The model editor shows the **effective multi-GPU state**: distribution controls appear for models inheriting the global default, single-GPU controls hide when they do not apply, and a hint marks settings that come from global defaults
- Models still pinned to one GPU under inherited multi-GPU get an **amber notice naming the GPU** with a one-tap "Remove pin"
- Model browser installs persist your **offload intent** (auto, CPU, GPU, mixed) instead of a hardware-specific layer count, so adding VRAM later is actually used
- Toggling global multi-GPU offers to **reconfigure existing models** so stale layer counts and pins are reset in one step
- Model loading shows a **single toast with per-GPU progress bars** instead of one bar per device
- Deleting a model file from Installed Models **warns when a configured model, vision adapter, MTP draft, or global default still references it**, listing exactly what would break, without blocking the delete

## Guided Tours

- **Local model editor**: context length, quick presets, GPU offload, and the last-run report explained the first time you open a llama.cpp model's runtime settings
- **Runtime defaults**: what global defaults do and how per-model overrides relate to them
- **Model browser**: the recommendation panel introduces itself as a whole, then walks quantization, context cost, offload choice, and KV cache placement, ending on the settings-versus-files tabs
- **Group chats**: group settings, participants, shared group memory, and the composer
- **Dynamic memory**: the enable toggle, run modes, memory profiles, and the embedding model section
- The tour engine now **scrolls partially visible targets into view**, top-aligns targets taller than the screen, and places its card beside full-height panels instead of on top of them

## Fixes

- **Companion souls are written by the Soul Writer model again**: the character's own model no longer silently overrides the model chosen under Settings, and the "Uses ..." label now names the model that will actually write the soul
- ASR learning data (vocabulary, corrections, ignored suggestions) is included in **backups** and restores cleanly on both import paths
- Sprout hardware reports are **validated against their schema version** before scoring runnability
- Desktop **back navigation** no longer strands you on the settings root, and the mobile settings back flow was corrected
